# 拾光笺备份格式 v1

文件扩展名 `.daybook`，内部为标准 ZIP。不是 SQLite 数据库的二进制复制。

应用从 v0.2 起更名为「拾光笺」；格式版本仍为 1，继续兼容原「日有记」v0.1 备份。应用名称和 appVersion 不作为备份格式是否可读的判断依据。

```text
manifest.json
entries.jsonl
drafts.jsonl
media/<sha256>.jpg | .png | .webp
```

## 清单

manifest 包含 `formatVersion=1`、`appVersion`、`exportedAt`、`files` 和 `assets`。

files 中每个文件记录相对路径、字节数和 SHA-256，不包含 manifest 自身；assets 记录内容摘要、MIME、尺寸、字节数和对应相对路径。图片 id 等于其 SHA-256。

## 事项和草稿

每个 JSONL 文本行是一个完整对象，UTF-8 编码，正文换行以 JSON 字符串转义保存。

事项包含 id、date、minute、title、body、createdAt、updatedAt、revision、deletedAt、assets 和 restoredFromId。assets 为保持用户图片顺序的图片 ID 数组。minute 为当天第几分钟，0～1439。

草稿包含 id、sourceEntryId、baseRevision、date、minute、title、body、updatedAt 和 assets。允许空正文且无图片的未完成草稿。源事项版本不一致的恢复草稿作为独立草稿保存。

日期为 ISO 日历日期，系统创建时间为 UTC epoch 毫秒。显示偏好不在 v1 备份内，恢复不会替换当前主题或字号。缩略图可重建，不占用备份空间。

## 校验和限制

- 清单必须与 ZIP 文件一一对应，不接受路径越界、绝对路径、反斜线、重复路径、未知格式版本。
- 每个文件验证声明大小与 SHA-256；图片内容还要核对真实格式和像素尺寸。
- 备份和展开后的数据各限制 8 GiB；事项与草稿各最多 50,000 条；单个 JSONL 文件最多 128 MiB，清单最多 16 MiB。
- 单图最大 25 MiB、5000 万像素；每条最多 9 张。首版支持 JPEG、PNG、静态 WebP。
- 图片必须有对应资产信息；不能将缺失图片当作正常恢复结果。
- SHA-256 提供完整性检查，不提供加密或备份身份认证。

## 合并

同 ID、内容相同跳过；同 ID、内容不同保留本机版本并生成带来源标记的恢复副本。恢复凭据按来源 ID、规范化内容指纹和类型去重，重复恢复同一冲突版本不会再次生成副本。

预览不是数据库提交：确认恢复时再次检查当前数据。图片先完整写入不可变文件，然后在 Room 事务内整体提交记录、关联与恢复凭据。校验失败不写现有记录；事务失败回滚业务数据，可能留下随后回收的未引用图片文件。
