# 拾光笺 v0.3 技术方案

方案日期：2026-10-25。开发基线：已交付的 v0.2.1。状态：待实施技术设计。

本版完整纳入七项功能：标签分类、按年月快速跳转、收藏、应用锁、往日此刻、古风长图导出、加密备份。本文明确产品规则、工程改造、数据升级和验收条件；文中的性能指标为开发目标，尚未实测。

## 1. 版本目标与范围

继续采用完全离线的原生 Android 架构。记录的文字、图片、标签、查询、回顾、渲染、认证和备份加解密均在设备上完成，不增加服务器、账号或网络权限。

| 功能 | v0.3 交付行为 | 主要入口 |
| --- | --- | --- |
| 标签分类 | 自定义标签、给记录添加多个标签、筛选、重命名和删除标签 | 编辑页、全部页、设置 |
| 年月跳转 | 选择有记录的年份和月份，直接定位时间轴，并可继续浏览前后月份 | 全部页日期按钮 |
| 收藏 | 收藏/取消收藏，集中查看收藏记录，可叠加标签筛选 | 时间轴、详情、全部页 |
| 应用锁 | 指纹等强生物识别或设备锁屏凭据解锁，后台超时锁定、立即锁定 | 设置、启动锁屏页 |
| 往日此刻 | 往年今日、往年本月；没有内容时首页不显示入口卡片 | 全部页回顾卡片 |
| 古风长图 | 导出一条或一天的记录，预览、保存、主动分享；过长内容自动分图 | 详情、按日页 |
| 加密备份 | 密码保护的完整备份、跨设备恢复、兼容读取旧备份 | 设置 → 备份与恢复 |

版本号计划为 `0.3.0`，versionCode 在现有 3 的基础上递增；包名继续为 `cn.ray.daybook`，minSdk 继续为 26。正式实现时再更新应用版本，本次方案不改变现有安装包。

## 2. 页面与交互

底部维持「全部 / 按日 / 日历 / 设置」，新增能力放在已有页面内。

### 2.1 全部页

从上到下排列：应用标题与搜索/记一笔 → 题签 → 可选的往日此刻卡片 →「全部 / 收藏」切换 → 标签筛选 → 年月定位 → 按日期分组的时间轴。

- 标签支持多选，默认含义为“包含任一所选标签”；与收藏、关键词、日期范围组合时，各类条件之间取交集。界面显示已选标签及清除入口。
- 年月选择器显示当前筛选条件下的月记录数；无记录月份禁选。选择月份是定位操作，不额外施加“仅看此月”过滤。
- 定位后先显示该月最新一条，再向下浏览更早记录；向上可加载更近的记录。提供「回到最新」按钮。
- 时间轴增加收藏按钮和标签行；点击记录进入详情，点击图片进入查看器。返回时恢复当前筛选、锚点和阅读位置。
- 切换筛选条件回到新结果顶部；仅打开详情再返回不清空筛选、不跳位。

### 2.2 编辑、详情与按日页

- 编辑页正文和图片优先，标签选择放在日期、时间附近；支持直接新建标签。标题继续选填。
- 详情增加收藏、标签展示和「导出长图」；按日页提供「导出这一天」。
- 日长图默认包含当天全部未删除记录；预览中可取消勾选不想导出的事项。默认按时间从早到晚排版。
- 收藏只作用于正式记录；未保存的草稿先保存后收藏。

### 2.3 设置页

新增「标签管理」「隐私与应用锁」「备份与恢复」分组。标签管理显示使用中的正式记录数；删除前说明将从记录和草稿中移除标签，不删除正文和图片。

回顾页分为「往年今日」「往年本月」。锁屏页仅展示应用名、解锁按钮与认证状态，不展示记录数量、标题或图片。

## 3. 技术栈与工程改造

沿用 Kotlin、Compose、Room、DataStore、Coroutines、Coil 本地图片加载及现有字体。保留单 app 模块，将当前较集中的 ViewModel 和页面文件按功能拆分。

| 新增能力 | 实现选择 | 目的 |
| --- | --- | --- |
| 时间轴分页 | Paging 3 + Compose；自定义游标 PagingSource，由 Room DAO 查询 | 避免现有 LIMIT 每次加 50 后重新加载全部已读记录 |
| 系统认证 | AndroidX Biometric + Keyguard 兼容层 | 使用设备已有认证能力，无自建密码库 |
| 长图排版 | Android Canvas + StaticLayout + 本地字体、采样图片 | 支持离屏排版，不依赖截取屏幕或无限高 Compose 组件 |
| 加密大文件 | Tink Streaming AEAD；JCA 密码派生与小型密钥封装 | 流式处理备份，避免完整文件进入内存 |
| 迁移测试 | Room testing / MigrationTestHelper | 验证数据库版本 1 → 2 |

新依赖加入 `gradle/libs.versions.toml`，通过兼容性验证后锁定具体稳定版本，不使用动态版本。现有 AGP、Kotlin、Compose 和 Room 不因新增功能而整组升级；若新依赖要求升级，先单独完成构建及回归验证。Tink 仅使用本地 Android 库，不引入任何 KMS 或云客户端。其 Android 支持范围覆盖本项目的 API 26 基线。[Tink Android 接入说明](https://developers.google.com/tink/setup/java)

建议职责划分：

```text
MainActivity / AppRoot
  ├─ AppLockController + AuthenticationGateway
  └─ NavigationState + 页面
       ├─ TimelineViewModel → TimelineRepository / PagingSource
       ├─ EditorViewModel   → DaybookRepository / TagRepository
       ├─ MemoriesViewModel → MemoriesRepository
       ├─ ExportViewModel  → CardExportService
       └─ BackupViewModel  → BackupService → ArchiveCodec + BackupCrypto

Room v2 / 不可变原图 / 私有临时目录 / DataStore
```

本版继续使用现有显式页面导航，不同时迁移整个导航框架。新增类型化的页面来源及会话状态：列表状态按筛选条件保存，详情按记录 ID 区分，编辑按草稿 ID 区分，查看图片和导出预览按本次打开的会话区分。避免再次出现不同记录共用旧滚动位置或图片页码的问题。

## 4. 数据结构与迁移

### 4.1 Room 版本 1 → 2

| 表 | 变更 |
| --- | --- |
| entry | 新增 `isFavorite INTEGER NOT NULL DEFAULT 0`、`favoriteUpdatedAt INTEGER NOT NULL DEFAULT 0`、`monthDay TEXT NOT NULL DEFAULT ''` |
| tag（新） | `id TEXT PRIMARY KEY`、`name TEXT NOT NULL`、`normalizedName TEXT NOT NULL`、`createdAt INTEGER NOT NULL`、`updatedAt INTEGER NOT NULL`；normalizedName 唯一索引 |
| entry_tag（新） | 联合主键 `(entryId, tagId)`；分别外键关联 entry、tag，删除时级联移除关系；增加 tagId 索引 |
| draft_tag（新） | 联合主键 `(draftId, tagId)`；分别外键关联 draft、tag；增加 tagId 索引 |
| 现有媒体、草稿、恢复凭据表 | 保留现有数据与主键 |

迁移中先添加字段和新表，再执行 `UPDATE entry SET monthDay = substr(entryDate, 6, 5)`。monthDay 是日期的派生值；所有新建、改日期及恢复路径都统一计算，不从备份接受一个独立可冲突的 monthDay。

新增候选索引：

- 全部时间轴：`(deletedAt, entryDate, minuteOfDay, createdAt, id)`。
- 收藏时间轴：`(deletedAt, isFavorite, entryDate, minuteOfDay, createdAt, id)`。
- 往年今日：`(deletedAt, monthDay, entryDate)`。

保留旧索引，先通过 `EXPLAIN QUERY PLAN` 与实际数据集验证，再决定是否删除冗余索引。筛选 SQL 使用 EXISTS 关联标签，避免多标签 JOIN 造成同一条记录重复出现。

实现显式 `MIGRATION_1_2`，在 `DaybookApplication` 的数据库 builder 注册。旧记录默认未收藏、无标签；旧图片及草稿继续可用。禁止破坏性迁移。使用已有 schema 1 构造旧库，再校验迁移后的结构、内容、图片引用、回收站和恢复凭据。[Room 迁移与测试](https://developer.android.com/training/data-storage/room/migrating-db-versions)

### 4.2 标签规则

- 默认限制：标签名 1～12 个 Unicode 码点；单条记录/草稿最多 5 个标签；全库最多 200 个标签。统一由 Rules 校验，UI 展示相同规则。
- 名称去除首尾空白、合并连续空白；查重键进一步执行 NFKC 规范化及 Locale.ROOT 小写转换。保留处理后的展示名称，不将正文套用此规则。
- 同名标签复用；名称只在本机唯一。恢复时允许不同 UUID 按规范化名称合并。
- 标签重命名保留 ID、更新所有展示，不改正文。重命名为已存在标签时提示重名，本版不提供隐式合并。
- 删除标签在事务中移除 entry_tag、draft_tag 和 tag；不删除任何记录或草稿。界面提示受影响数量，活动草稿刷新标签选项。
- 为记录增删标签视为一次记录编辑，递增现有 revision；全局删除标签也递增受影响记录的 revision。若已有编辑草稿发生版本冲突，保留其文字和图片，让用户确认后重新提交，不静默覆盖。

### 4.3 收藏与草稿的并发规则

收藏通过独立 DAO 更新 isFavorite 和 favoriteUpdatedAt，不递增正文编辑使用的 revision。保存已有记录时，从数据库读取并保留当前收藏值，不使用旧草稿快照覆盖收藏。

收藏与取消收藏允许立即撤销；写入失败回滚显示并提示。删除到回收站保留收藏和标签关系，普通收藏列表排除回收站；恢复后回到原来的分类状态。

编辑草稿复制 entry_tag 到 draft_tag。自动保存、正式保存、备份、恢复都包含草稿标签；正式保存时在同一个事务中替换记录标签、更新正文和图片关系、删除草稿。

## 5. 全部、收藏、标签查询与年月定位

### 5.1 统一查询状态

```kotlin
data class TimelineFilter(
    val favoriteOnly: Boolean,
    val tagIds: Set<String>,
    val query: String,
    val from: LocalDate?,
    val until: LocalDate?
)
// 实际实现使用可序列化的轻量值保存筛选与锚点，不把完整记录放进 Bundle。
```

时间轴、搜索结果、收藏和年月计数复用相同过滤规则。顺序继续为 `entryDate DESC, minuteOfDay DESC, createdAt DESC, id DESC`，保证同一时间多条记录的排序稳定。

### 5.2 游标分页

使用四字段元组 `(entryDate, minuteOfDay, createdAt, id)` 作为游标，DAO 用参数化的逐字段比较表达严格大小关系。默认每页 50 条，预取 10 条，内存中保留约 200 条；具体配置在性能验收中调整。

- 向更早加载：查询小于末条游标的数据，按倒序取一页。
- 向更新加载：查询大于首条游标的数据，按正序取一页，再反转为显示顺序。
- 初始年月定位：使用所选月下月第一天作为独占日期上界，加载第一批内容；月计数确保所选月在当前筛选下确有记录。
- 刷新：依据正在阅读的记录 ID 和游标重建相邻页面，不使用旧列表下标作为唯一定位依据。
- 标签、收藏、记录及媒体关联变化时，通过 Room InvalidationTracker 使 PagingSource 失效并重新创建；观察者随 PagingSource 生命周期释放。
- 每页的记录和图片/标签关联在短事务中读取。不得对每条记录单独发一次图片或标签查询。
- 日期分组使用稳定日期 key，跨分页边界只生成一个日期标题；刷新、预取和滚动回收不能造成重复事项或漏项。

分页采用 Android Paging 的数据源与展示模型；游标比较和年月锚点是本项目的业务实现。[Paging 官方说明](https://developer.android.com/topic/libraries/architecture/paging/v3-overview)

### 5.3 状态恢复

保存筛选条件、目标月份、可见记录 ID、游标和像素偏移；进程重建后先查询再恢复位置。锚点记录被删除时，选择其排序位置附近的下一条；过滤后为空时展示空状态和清除筛选按钮。

从编辑保存返回时，新建记录回到对应结果中的可见位置；若记录不符合当前筛选，明确提示「已保存，当前筛选下不显示」，提供查看入口。丢弃草稿及详情返回继续遵循 v0.2.1 的来源页面规则。

## 6. 往日此刻

- 「往年今日」：monthDay 等于设备今天的月日，且 entryDate 严格早于今年 1 月 1 日，排除回收站。
- 「往年本月」：逐年构造当前月份的日期区间，按年分组；只查询今年之前的数据。
- 只采用公历所属日期，暂不做农历周年换算。2 月 29 日只在闰年的 2 月 29 日展示同日记录，不自动归入 2 月 28 日；平年 2 月可在往年本月中看到它们。
- 首页有往年今日时优先展示，否则有往年本月时展示月回顾；两者都无内容则不占首页位置。卡片只展示少量摘要，点击进入完整分页列表。
- 回顾独立于首页当前收藏/标签筛选，页面明确说明“往年全部记录”；用户可在回顾页再筛选收藏或标签。
- 回顾不产生重复记录、不写入每日快照、不安排通知或后台定时任务。
- 注入可测试的 Clock 和 ZoneId；在前台跨零点、重新进入前台或系统日期/时区变化时重新计算今天。原记录所属日期保持固定。

## 7. 应用锁

### 7.1 认证方式与 Android 兼容

使用设备已有的强生物识别和锁屏 PIN、图案或密码，不创建应用专属密码，不采集生物特征。

| 系统版本 | 认证路径 |
| --- | --- |
| Android 11 / API 30 及以上 | AndroidX BiometricPrompt，允许 `BIOMETRIC_STRONG | DEVICE_CREDENTIAL` |
| Android 8～10 / API 26～29 | 强生物识别单独使用 BiometricPrompt；设备凭据走 KeyguardManager 的兼容认证 Activity，不传入不受支持的组合 |

接入 AndroidX Biometric 时将 MainActivity 改为 FragmentActivity，继续承载 Compose。认证回调绑定 Activity 生命周期，处理取消、锁定、硬件不可用与配置变化；不能把“对话框结束”当作认证成功。API 29 及以下的认证组合限制按官方说明处理。[Android 生物识别认证](https://developer.android.com/identity/sign-in/biometric-auth)

开启前检查设备安全锁屏，并要求一次成功认证。设备未设置锁屏时引导设置后重试。开启、关闭应用锁和修改锁定策略均需认证；不提供跳过验证的关闭入口。

### 7.2 锁定状态机

```text
启动 / 进程重建 → 读取锁配置
  ├─ 未启用 → 展示应用
  └─ 已启用 → Locked → Authenticating → 成功后 Unlocked
                                  └─ 取消/失败 → Locked

Unlocked → 进入后台并记录单调时钟 → 返回时判定是否超时
Unlocked → 熄屏 / 点击立即锁定 → Locked
```

- DataStore 配置未读取完成时只显示启动占位，不先显示日记。读取失败保留遮罩并允许重试，不能把错误解释成“未启用锁”。
- 默认后台 30 秒后需要重新解锁，可选立即、30 秒、1 分钟、5 分钟；冷启动始终要求解锁，熄屏立即锁定。
- 超时使用 SystemClock.elapsedRealtime，不受手动修改时间影响；跨进程不恢复“已解锁”状态。
- 锁定时移除敏感页面的可见/可访问性子树；保留编辑模型并尽力保存草稿，不能因此丢弃正文。认证失败不会清空数据。
- 配置变化不作为真实后台超时；后台判定用生命周期协调器，但遮挡内容不依赖有延迟的进程 ON_STOP 通知。
- 系统认证界面本身不触发循环锁定。文件选择器、分享界面返回时仍检查会话；待处理 URI 只在重新解锁后交给业务层。可持久化的 URI 权限按返回授权取得，无法保留时提示重新选择。
- 锁定后阻止新的保存、导出、恢复等用户操作；已开始的数据库事务必须原子完成或回滚。文件导出遇到锁定请求协作取消并清理未发布文件，不在锁定状态继续发布内容。
- 如果用户在系统中移除设备锁屏，应用保持锁定，说明需重新设置设备锁屏后认证；不能自动降级成直接放行。

### 7.3 隐私边界

启用应用锁时给承载敏感内容的窗口设置 FLAG_SECURE，限制系统截图、录屏和最近任务预览；密码备份输入页也应用该策略。系统与厂商行为必须真机验证。[FLAG_SECURE 定义](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE)

应用锁保护访问入口，数据库和应用私有原图仍采用现有存储方式；本版不宣称实现整库、原图静态加密或抵御 root/调试读取。锁配置不进入跨设备备份，恢复后沿用目标设备设置。开启应用锁也不会撤回已经由用户导出的长图或文件。

## 8. 古风长图导出

### 8.1 导出内容与流程

提供一套与现有界面一致的宣纸、墨色、朱砂模板：日期题签、左侧竖线、时间节点、标题、正文和图片。时间默认显示，标签默认隐藏且可开启；不添加账号、定位、内部 ID 或强制水印。

```text
选择一条/一天 → 获取固定内容快照 → 测量与分页 → 低分辨率预览
→ 用户选择保存或分享 → 渲染正式图 → 写入并复核 → 显示结果
```

快照包含记录内容、标签名称、图片引用和排版配置。记录随后被编辑不改变已显示的预览；点击重新生成才更新快照。取得快照时保护相关图片资源，防止永久删除/清理与渲染并发导致缺图。

资源保护由统一文件操作协调器维护活动引用，长图结束后释放；备份、导入和清理也检查活动引用。锁定、取消和进程重启清理临时任务状态，不持有覆盖整个绘图过程的数据库事务。

### 8.2 排版与内存

- 输出宽度默认 1080px，单张最大高度 6000px；ARGB 位图约 25MiB。一次只渲染一张，并限制同时解码的照片尺寸与数量。
- 使用 StaticLayout 处理中文换行、emoji、长英文、空行与字体回退；沿用随包 Noto Serif SC，并记录导出样式版本。
- 排版采用“测量 → 生成绘制块 → 按安全边界分页 → 逐页渲染”。长正文可在行边界分段，图片网格在行边界分页，不能截断文字或漏掉超长单条记录。
- 图片按输出区域采样并处理 EXIF 方向，完整显示照片内容。只解码当页所需资源；缩略预览不保留所有原尺寸成图。
- 超过单图高度自动输出连续编号的多张长图，并显示“共 N 张”。默认单任务最多 20 张；超过时在预览前提示减少勾选事项，不能静默截断。
- 缺图、解码失败或空间不足不生成假成功结果；展示具体失败项，保留导出选择供重试。
- 默认 PNG，兼顾文字清晰度；新生成图片不复制原图 EXIF 和定位元信息。

### 8.3 保存与主动分享

- API 29 及以上：通过 MediaStore 写到 `Pictures/拾光笺/`，写入阶段使用 IS_PENDING，全部对应文件准备成功后再逐个发布；失败清理本次创建的条目。多文件发布不具备跨文件事务，部分发布失败须明确报告并尽力回滚。
- API 26～28：通过 SAF 保存图片；多图可让用户选择目录。按钮明确显示「保存到所选位置」，不承诺系统相册立即收录，以避免新增广泛存储权限。
- 分享：用户点击后启动系统 Sharesheet，使用 FileProvider 提供临时只读 content URI；多个文件使用 ACTION_SEND_MULTIPLE。仅暴露专门的导出缓存目录，不暴露原图或整个 filesDir。
- 临时分享文件保留最长 24 小时，在后续启动/操作时清理并撤销授权。取消系统分享不显示“已发送”，应用无法确认接收方是否最终发布。
- 导出预览说明“保存到相册或分享后的图片不受应用锁保护”。开启应用锁时，输出前重新确认会话有效。

依据：[MediaStore 写入与待发布状态](https://developer.android.com/training/data-storage/shared/media)、[FileProvider 文件分享](https://developer.android.com/training/secure-file-sharing/share-file)。

## 9. 逻辑备份格式 v2 与旧备份兼容

数据库版本、逻辑备份版本和加密容器版本相互独立：本版分别为 Room 2、逻辑备份 2、加密容器 1。

### 9.1 内层归档

```text
manifest.json        formatVersion=2、appVersion、导出时间、文件/图片清单
entries.jsonl        原字段 + isFavorite、favoriteUpdatedAt、tagIds
drafts.jsonl         原字段 + tagIds
tags.jsonl           标签 ID、展示名、规范化名、创建/修改时间
media/<sha256>.*     原图片
```

未加密时继续使用 `.daybook`；加密时使用 `.daybook.enc`。读取依据文件 magic 与 manifest，不仅依赖后缀。备份包括未使用标签、草稿、回收站、收藏与图片，不包含锁配置、解锁会话、密码、缩略图和导出缓存。

新版分别使用 v1/v2 DTO 严格解析，不能直接向现有 v1 对象添加未知字段后假设旧程序能读取。v0.2.1 的解析器会拒绝新字段/版本，因此旧 App 无法恢复 v2；界面与说明明确提示，新版可以读取旧版。

| 输入 | v0.3 行为 |
| --- | --- |
| v1 明文 .daybook | 校验后升级为内部模型；新导入记录默认无标签、未收藏 |
| v2 明文 .daybook | 完整读取标签与收藏 |
| 加密容器 1 | 输入密码，完整认证解密后，再判断内层逻辑版本 |
| 未知逻辑/容器版本 | 拒绝导入并提示需要兼容版本，不部分恢复 |

### 9.2 合并与去重

保留现有“同 ID 不同正文/图片保留双方”的原则，并将分类信息与正文冲突分开处理。

1. 保留 v1 已使用的内容指纹算法和 restore_receipt 含义，不能给旧指纹直接追加标签/收藏而导致旧备份重复生成副本。
2. v2 额外计算分类指纹：收藏布尔值 + 按规范化名称排序的去重标签集合；不使用映射后的本机标签 UUID 计算分类相等。
3. 正文内容相同、分类不同：不复制整条日记。预览列出分类差异数量，默认保留本机分类，可选择本次恢复使用备份分类。v1 没有分类信息，永远不据此清空本机收藏或标签。
4. 正文不同：创建恢复副本，附带备份中的收藏与标签。已存在旧恢复凭据时先找到原副本，再执行分类差异判断，不能因凭据存在而完全忽略 v2 分类信息。
5. 标签先按 normalizedName 匹配本机标签；未匹配且 UUID 无冲突时保留 UUID；UUID 已被不同名称占用时生成新 UUID。统一维护源标签 → 本机标签映射，再写入记录/草稿关系。
6. 重复恢复同一份备份不新增相同标签、日记副本或草稿。删除标签后再次导入该备份，按本次选定的分类恢复策略处理，不靠遗留凭据错误阻止合法恢复。
7. 草稿的正文/图片身份保持旧规则；新增标签差异使用同类显式策略。源事项冲突仍降为独立恢复草稿，不覆盖现有正式记录。

恢复后的标签总量和单条标签数仍需满足限制；预览发现超限时停止并说明所需调整，不静默丢弃标签或只恢复部分数据。

预览与最终提交共用 RestorePlanner；提交在获得写锁后重新检查分类、版本和资源空间。先完成图片文件落盘，再在同一个 Room 事务中提交标签、记录、关系与凭据。

## 10. 密码加密备份

### 10.1 密码与算法

备份界面默认选择密码加密；保留用户主动选择明文导出的选项，并显示其包含可读取的文字和照片。设置备份密码时输入两次，建议长口令，产品最低长度 10 个 Unicode 码点、上限 128；不强制符号组合。

密码原样使用，不 trim、不做大小写或 Unicode 归一化；密码字节约定为 UTF-8，中文、空格及 emoji 都需跨设备测试。密码不保存到 DataStore、SavedStateHandle、日志或备份正文，不绑定当前手机的生物识别或 Keystore，因此可换设备恢复。忘记备份密码无法找回该文件中的内容。

| 用途 | 设计参数 |
| --- | --- |
| 密码派生封装密钥 KEK | PBKDF2-HMAC-SHA256，随机盐 32 字节，初始写入参数 600,000 次，输出 256 bit |
| 包装本次数据密钥集合 | AES-256-GCM，随机 nonce 12 字节、tag 128 bit，仅处理小型 Tink keyset |
| 加密大备份 | Tink Streaming AEAD，`AES256_GCM_HKDF_1MB`，每次备份随机生成全新 keyset |
| 随机源 | 平台 SecureRandom；每次导出重新生成盐、nonce、数据密钥 |

PBKDF2 选择基于 Android 标准实现与跨设备部署成本；600,000 次参考 OWASP 对 HMAC-SHA256 的工作因子建议，不表示本产品取得任何合规认证。开发时在 API 26 的低性能设备验证耗时，保留进度与取消反馈，不为追求速度静默降低已约定的强度。[OWASP 密码派生参数参考](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

Tink 负责大文件分段加密及认证，应用不自行设计分块 nonce 或截断验证协议。使用标准 JCA AES-GCM 只封装小型密钥集合，避免一次性 GCM 解密几 GiB 文件可能引入的缓冲问题。[Tink Streaming AEAD](https://developers.google.com/tink/streaming-aead)

### 10.2 外层容器 1

```text
Magic[8] = ASCII "SGJENC01"
HeaderLength[4] = 无符号大端整数
Header[HeaderLength] = UTF-8 JSON，最多 16 KiB
WrappedKeysetLength[4] = 无符号大端整数
WrappedKeyset[WrappedKeysetLength] = 最多 64 KiB
Payload[...] = Tink Streaming AEAD 密文流
```

Header 只含容器版本、KDF/算法标识、迭代次数、盐、封装 nonce、随机 archiveId 和 streaming 算法标识。不暴露记录标题、标签、数量、日期或原文件名；文件总大小及通用加密参数仍可见。

- 密钥封装的 AAD：固定域分隔符 `SGJ/KEY/v1` + magic + headerLength + 原始 header 字节。
- 正文流的 AAD：固定域分隔符 `SGJ/PAYLOAD/v1` + 前述头部 + wrappedKeysetLength + wrappedKeyset。
- 认证使用读取时的原始字节，不重新格式化 JSON。解析器拒绝重复字段、未知算法和不符合长度的盐/nonce。
- 先验证所有字段长度和参数范围，再做密码派生。容器 1 仅接受 600,000～2,000,000 次的迭代参数；超出范围直接报不支持，避免恶意大数占满 CPU。新写入固定使用 600,000 次。
- 从内存序列化 Tink keyset，包装后尽快擦除临时字节数组；解密后同样及时清理。明文 keyset 永远不写入磁盘。JVM 中无法保证所有字符串/库内部副本即时擦除，不作此承诺。
- 包装密钥认证失败统一提示「密码不正确或备份已损坏」；未认证前不展示内容预览。

实现前生成固定测试向量，并验证不同进程/设备间的密码编码、keyset 序列化与容器可读性。未完成互操作验证前不冻结对外格式。

### 10.3 导出、解密与提交时序

导出：落盘草稿 → 建立一致的逻辑快照 → 写私有 v2 ZIP 并校验 → 流式加密到私有临时文件 → 流式解密复核摘要及结尾认证 → 删除明文临时 ZIP → SAF 写出密文 → 重新打开目标比对密文摘要 → 更新成功备份时间。

恢复：复制用户文件到私有 staging → 有界解析头部 → 输入密码、解开 keyset → 流式解密至私有 ZIP → **读到流末尾且所有认证成功** → 校验 ZIP、JSONL 和图片 → 显示恢复预览 → 用户确认后事务提交。

Tink 可逐段返回已认证明文，但应用必须等整条流成功结束后才能预览或恢复，避免一个被截断文件的有效前缀被当作完整备份。任何认证、解压或引用校验失败都删除本次临时产物，不修改已有业务数据。依据：[Tink 大文件加解密示例](https://developers.google.com/tink/encrypt-large-files-or-data-streams)。

### 10.4 大文件、空间与中断

- 保留逻辑 ZIP 与展开数据各 8 GiB 上限；外层密文上限为 8 GiB + 16 MiB，为认证开销留余量。JSONL、清单、单图等限制继续独立校验。
- 加密额外缓冲以 1 MiB 分段为主；不能对整个文件 readBytes。现有 BackupService 的全量记录列表需要改为分批导出、逐行校验；大恢复计划放入 staging 临时 SQLite 索引，不将所有正文、图片元信息和冲突计划同时常驻内存。
- 导出快照在统一写入协调区分批读取，阻止并发写入破坏一致性；原图保持不可变。元数据快照完成并注册资源保护后释放写锁，文件复制期间避免数据库长事务。
- 恢复预览不长期占用正式库写锁；最终提交重新生成冲突计划，业务合并仍使用单事务，失败整体回滚。
- 空间预估包含内层 ZIP、外层密文、解密文件、展开文件、新增原图、临时索引及 WAL。检查保守峰值，所有写入仍处理 ENOSPC；不能只看最终备份大小。
- 任务为前台操作，显示阶段、进度和取消入口。进程被终止时从头重试；不自动续写密文，不复用上次 nonce/keyset。
- 失败、取消和下一次启动清理本次私有临时目录；路径必须限定在指定 staging 根目录。外部不完整文件尽力删除，无法删除时告知位置。
- 明文临时文件仅在应用私有目录中存在；删除不等于闪存安全擦除。当前应用原数据库和原图仍按现有私有存储方式保存。

## 11. 权限与离线约束

Manifest 继续不声明 INTERNET、不引入网络图片加载或分析 SDK。预计仅新增认证所需的 USE_BIOMETRIC，以及兼容旧 API 时库要求的 USE_FINGERPRINT；通过合并 Manifest 实际复核。

FileProvider 为 `exported=false`、允许临时 URI 授权，仅配置导出缓存子目录。MediaStore 保存采用自有媒体路径；旧版本用 SAF，避免 READ_MEDIA_IMAGES、广泛存储访问和 MANAGE_EXTERNAL_STORAGE。

原有 allowBackup=false 与系统云备份/设备迁移排除继续适用于数据库、图片、锁配置和临时文件。应用内主动生成的备份是独立的用户操作。系统分享目标由用户选择，其后续联网行为由目标应用负责。
