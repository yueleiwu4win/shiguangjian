# 拾光笺

完全离线的原生 Android 私人事记。默认首页查看全部记录，按日期分组、由近及远展示；也可按天查询，一天多条记录，文字与图片均可独立成条。界面采用宣纸色、朱砂点缀和左侧竖向时间轴。

当前版本 0.2.1，应用名为「拾光笺」，首页题签为「日常拾记」。底部入口：全部 / 按日 / 日历 / 设置。安装包位于 `dist/shiguangjian-0.2.1-debug.apk`。

下一版七项功能的待实施设计见 [拾光笺 v0.3 技术方案](docs/拾光笺-技术方案-v0.3.md)，覆盖标签、年月跳转、收藏、应用锁、往日此刻、长图导出与加密备份。

## 运行与构建

建议 Android 8.0 及以上手机。源码使用 Kotlin、Jetpack Compose、Room 与 DataStore；无服务器、账号和网络权限。

在 Android Studio 中打开本目录，使用 JDK 17、Android SDK 35。所有依赖版本由 `gradle/libs.versions.toml` 固定。首次构建需要下载开发依赖，安装后的 App 运行无需网络。

```powershell
# 有项目本地工具时自动使用；也支持 JAVA_HOME / ANDROID_HOME。
.\build.ps1

# 标准 Gradle Wrapper，跨平台使用同一工程。
.\gradlew.bat assembleDebug testDebugUnitTest verifyOfflineManifest lintDebug

# 已连接专用测试设备时执行仪器测试。
.\gradlew.bat connectedDebugAndroidTest
```

默认任务生成可安装的测试 APK：`app/build/outputs/apk/debug/app-debug.apk`。

`assembleRelease` 会生成未签名的发布包。正式分发需由项目所有者提供并保管发布签名，不将密钥、口令提交到源码。测试版使用开发签名，不能承诺与未来不同签名的正式版直接覆盖安装；换签名前先导出手动备份。

本次准备的本地 JDK、SDK、Gradle 和测试设备位于忽略提交的 `.tools/` 内；这些不是成品 App 的组成部分。

## 已实现范围

- 默认显示全部事项，按日期分组，最新在前，每批 50 条，可继续加载更早记录；不展示回收站事项。
- 可切换按日时间轴、选择历史日期补记；点击全部列表中的日期可进入当天。
- 新建、编辑、纯文字、纯图片及图文事项，每条最多 9 张图。
- JPEG、PNG、静态 WebP 原片复制进私有目录，配合本地缩略图；单图 25 MiB / 5000 万像素上限。
- 本地自动草稿、继续编辑、主动丢弃；返回与进入后台时尽力落盘。
- 月历记录数、中文子串搜索、日期范围筛选与结果分批加载。
- 回收站恢复、单条永久删除、图片引用检查与清理。
- 本地 `.daybook` 备份：完整图片、正文、草稿、回收站；导出复核、恢复预览、合并与幂等去重。
- 跟随系统 / 浅色 / 深色与应用字号设置；标题字体随包提供。

初次安装数据库为空，不预置演示日记。图片必须从设备导入。

## 使用说明

首页右上角「记一笔」进入编辑。先输入文字或添加图片，再选日期、时间和可选标题。在全部页新建默认今天，保存后回到全部列表顶部；在按日或日历页新建默认当前查看日期。返回则保留草稿。草稿也可从设置页进入。

丢弃草稿后返回进入编辑前的页面；从全部列表进入时保留原阅读位置。每次点击图片均从本次选中的那张开始查看。

备份入口在设置页。选择本机或外部存储位置生成备份；恢复时先显示预览，再合并导入。相同 ID 与内容跳过，内容不同则保留恢复副本。备份格式详情见 [备份格式说明](docs/备份格式-v1.md)。

应用私有存储不等于内容加密。首版备份未加密，包含完整记录及原图片；卸载 App 会移除应用私有数据，请先把备份保存到应用目录之外。

## 工程结构与关键决策

```text
app/src/main/java/cn/ray/daybook/
  ui/                  古风主题、公共组件、页面
  model/               内容约束、可迁移数据格式与指纹
  data/                Room、文件导入、草稿、备份恢复
  DaybookViewModel.kt   页面状态、用户操作、自动草稿调度
app/src/test/          规则、格式与本地 Android 集成测试
app/src/sharedTest/    本地 Android / 设备共用的行为测试
app/src/androidTest/   真机/模拟器测试入口
app/schemas/          Room 历史 schema
docs/                 需求、技术方案、备份格式、验证记录
```

首版使用单 Activity 与显式页面状态导航，保存选中日期与草稿 ID；页面数据通过 Repository、ViewModel 和 StateFlow 更新。媒体使用 SHA-256 内容标识，在不同记录与备份恢复中可复用相同文件。

记录、草稿和媒体关联使用 Room 事务更新；文件先完整落盘，再提交数据库引用。数据库禁止破坏性迁移。下一次 schema 升级必须增加 Migration 与旧数据升级测试。

备份中图片关系内嵌于记录/草稿 JSONL 的有序 `assets` 数组，未另设重复的 relations 文件；备份包版本独立于 Room schema 版本。

## 验证与限制

当前修复与执行结果见 [v0.2.1 开发与验证记录](docs/开发与验证记录-v0.2.1.md)，此前记录见 [v0.2](docs/开发与验证记录-v0.2.md) 与 [v0.1](docs/开发与验证记录-v0.1.md)。

设备测试与 Robolectric 测试分别记录；Robolectric 通过不能代替厂商文件选择器、系统备份行为、真实触控和真机性能验证。当前工程包含对应设备测试入口。UI 仪器测试会清空测试应用数据库，请仅在专用测试设备执行，不要在存有真实日记的手机上运行仪器测试。

应用不申请 INTERNET、全部文件管理、相册全库、定位或联系人权限。系统文件选择器使用本地内容提示，但外部提供器的行为需要设备实测。首版未加入内容加密、应用锁、OCR、提醒、云同步、视频或拍照。
